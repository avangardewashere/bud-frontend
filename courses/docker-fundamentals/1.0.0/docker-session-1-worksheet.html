Theory

0/4

Read, then write the answer in your own words. If you can't fill the field without looking it up again, you haven't got it yet.

Environment drift, dependency mismatch, "works on my machine".

A VM ships its own kernel. A container shares the host kernel and isolates the process. That single difference explains the startup time and the image size.

Blueprint, running instance, and where blueprints are stored. Worth an analogy you'd actually use out loud.

CLI, then the daemon, then containerd, then runc. You don't need depth here, just the chain — it makes later error messages readable.

Hands-on

0/8

Run these in order. Read every line of output before moving on, even the boring ones.

Two versions print: Client and Server. Notice that they are separate things talking to each other.

docker version

It prints and stops. The container is finished but not gone — that distinction matters in a minute.

docker run hello-world

Then open localhost:8080. The left number is your machine, the right number is inside the container.

docker run -d -p 8080:80 --name web nginx

The second command shows hello-world still sitting there, exited. Nothing cleaned it up.

docker ps docker ps -a
docker logs -f web

A whole Linux filesystem, with almost nothing in it. Change the html file and reload the page in your browser.

docker exec -it web sh ls /usr/share/nginx/html echo "hello from inside" > /usr/share/nginx/html/index.html exit

Stop it, remove it, start a fresh one. Your edited page is gone. Session 6 is where you fix that on purpose.

docker stop web docker rm web docker run -d -p 8080:80 --name web nginx

One image, two independent containers on different ports. This is the point of the whole distinction.

docker run -d -p 8081:80 --name web2 nginx docker ps

Deliverable

0/3

This is the part that carries forward. Copy it into your notes.md when you're done.

Aim it at a frontend developer who has never touched Docker. If you need a metaphor, use one from your own work.

Two containers in the list is the better screenshot.

Two things that will trip you up today.

docker stop ends the process. docker rm deletes the container. Stopping something and then wondering why docker ps -a still lists it is the normal first confusion.

The port mapping is -p host:container, in that order. You will get it backwards at least once and see a page that never loads.
